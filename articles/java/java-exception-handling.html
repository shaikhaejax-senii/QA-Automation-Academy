Exception Handling in Automation

Exceptions are disruptions in the normal flow of the program. In automation, handling them prevents the entire test suite from crashing due to a single failure.

Types of Exceptions

  • Checked Exceptions: Checked at compile-time (e.g., `IOException`). You must handle them.
  • Unchecked Exceptions: Checked at runtime (e.g., `NullPointerException`, `NoSuchElementException`).

Try-Catch Usage

Wrap risky code in a `try` block. If an error occurs, the `catch` block executes.

try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero!");
}

Finally Block

The `finally` block executes always, regardless of whether an exception occurred or not. It is critical for resource cleanup.

Automation Use Case: Closing the browser or database connection.

try {
    // Run tests
} catch (Exception e) {
    // Log error
} finally {
    driver.quit(); // Ensure browser closes
}

Real Time Example

Handling `NoSuchElementException` when an element might not be present (e.g., a popup).

public boolean isPopupPresent() {
    try {
        driver.findElement(By.id("popup"));
        return true;
    } catch (NoSuchElementException e) {
        return false;
    }
}

Common Mistakes

  • Catching generic `Exception` everywhere instead of specific ones.
  • Swallowing exceptions (empty catch block) – this hides bugs!
