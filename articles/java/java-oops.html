Object Oriented Programming (OOP) in Java

Object Oriented Programming (OOP) is the backbone of Java and almost all modern test automation frameworks. Understanding these concepts is non-negotiable for a QA Engineer.

What is OOP?

OOP is a programming paradigm based on the concept of "objects", which contain data (fields) and code (methods). It aims to implement real-world entities like inheritance, hiding, polymorphism, etc. in programming.

Inheritance

Inheritance is a mechanism where one class acquires the properties and behaviors of a parent class.

Why use it in Automation? To create a `BaseTest` class that contains setup (`@BeforeMethod`) and teardown (`@AfterMethod`) logic. All test classes extend this `BaseTest`. 

public class BaseTest {
    WebDriver driver;
    
    public void setup() {
        driver = new ChromeDriver();
    }
}

public class LoginTest extends BaseTest {
    @Test
    public void validLogin() {
        setup(); // Inherited method
        // ...
    }
}

Polymorphism

Polymorphism allows us to perform a single action in different ways. In Java, we use Method Overloading and Overriding.

Real Time Example

In Selenium, `WebDriver driver = new ChromeDriver();` is a perfect example of Runtime Polymorphism. The reference variable is of type `WebDriver` (Interface), but the object is `ChromeDriver`. This allows us to easily switch to `FirefoxDriver` without changing code everywhere.

Encapsulation

Wrapping code and data together into a single unit. We use private fields and public getters/setters.

Automation Use Case: Page Object Model (POM). We declare WebElements as `private` and provide public methods to interact with them, preventing tests from directly manipulating elements.

Real Time Example

public class LoginPage {
    // Encapsulation: Private elements
    private By username = By.id("user");
    private By password = By.id("pass");
    
    // Public method to interact
    public void login(String u, String p) {
        driver.findElement(username).sendKeys(u);
        driver.findElement(password).sendKeys(p);
    }
}

Common Mistakes

  • Assuming every class needs to extend `BaseTest`.
  • Making all variables `public static` just to access them easily (destroys parallel execution).

Interview Questions

  • Q: Can we override static methods?
    No, static methods are bound to the class, not object. This is called Method Hiding.
  • Q: Why is Multiple Inheritance not supported in Java?
    To avoid the "Diamond Problem" of ambiguity.
  • Q: What is the difference between Abstract Class and Interface?
    Abstract class can have state (variables), Interfaces cannot (only constants).
