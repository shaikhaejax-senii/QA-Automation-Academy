Mastering Selenium Locators: XPath vs CSS

The most common reason for flaky tests is bad locators. If you rely on right-click -> "Copy XPath", your tests will fail. Here is how to write robust locators.

Locator Strategies

Selenium offers 8 locator strategies. You should prioritize them in this order:

  1. ID: Fastest and most unique.
  2. Name: Good for form elements.
  3. CSS Selector: Fast, readable, and powerful.
  4. XPath: Most flexible, capable of traversing up the DOM.

Writing Custom XPath

XPath allows you to find elements by their attributes, text, or relationship to other elements. 

// By Attribute
driver.findElement(By.xpath("//input[@data-testid='submit-btn']"));

// By Text Contains
driver.findElement(By.xpath("//button[contains(text(), 'Log In')]"));

// Parent to Child
driver.findElement(By.xpath("//div[@class='form-group']//input"));

CSS Selectors

CSS selectors are natively supported by browsers and are generally faster than XPath. 

// ID
driver.findElement(By.cssSelector("#submit-btn"));

// Class
driver.findElement(By.cssSelector(".primary-btn"));

// Attribute
driver.findElement(By.cssSelector("input[name='email']"));
